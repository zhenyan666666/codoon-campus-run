旧方案：系统级虚拟定位（Test Provider）—— 已废弃，仅留档
==========================================================

做法
----
用 root 在系统里建测试定位源，把模拟位置直接灌给 Android 的 location 服务：

  su 0 cmd location providers add-test-provider gps
  su 0 cmd location providers set-test-provider-enabled gps true
  su 0 cmd location providers set-test-provider-location gps --location 22.683778,114.202625 --accuracy 5

设备脚本 run_route.sh 会逐行读 route_samples.txt，每 0.95 秒把 gps/network 两个
provider 都设到下一个坐标点，实现"沿路线跑"。start_route.sh 用 setsid 启动它。

为什么废弃
----------
咕咚会检查定位结果的 mock 标记和卫星数（dex 里有 isFromMockProvider / getSatellites /
MOCK_LOCATION 等字符串），系统 Test Provider 给的位置带 mock 标记：
  - 咕咚能收到位置（dumpsys location 显示 locations 持续增长）
  - 但屏幕上距离一直是 0.00、配速 00'00"，跑 2 分钟也不涨
  - logcat 里大量 "non-monotonic location received from gps provider"

结论：系统级 mock 走不通，改用 frida 注入咕咚内部的高德定位 SDK（见工具包主方案）。

文件说明
--------
route_samples.txt  5400 个采样点（13 点闭环，362.2 米，3 m/s，约 90 分钟），每行 lat,lon,accuracy
run_route.sh       设备端播放器（读 /data/local/tmp/route_samples.txt）
start_route.sh     启动器（setsid 后台运行，避免 adb shell 退出时被杀）

如果想再试：
  adb push route_samples.txt /data/local/tmp/
  adb push run_route.sh /data/local/tmp/
  adb push start_route.sh /data/local/tmp/
  adb shell sh /data/local/tmp/start_route.sh
  停止：adb shell su 0 touch /data/local/tmp/route_stop
